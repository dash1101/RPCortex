# Testing RPCortex v2

One command runs everything that can be run without hardware:

```
cd os/host && ./run_all.sh
```

Seventy runs (every suite, plus the plain-allocator reruns), about half a minute, and the last line is the answer to one
question. **It is not the question "does the OS work".** What that line covers
and what it cannot is the last section of this file, and it is the part worth
reading first.

`realapp_test` loads the packages `build.sh` produces, so it fails in a tree
that has not built yet. It says so by name — which file is missing and which
command produces it — rather than checking whatever happens to be there.

---

## What is proven without a board

`os/core/` is deliberately free of hardware headers, which is what makes most of
the OS ordinary testable code. On top of that, `host/fakehw.cpp` implements the
package ABI, so packages — which only ever call `fw_*` — are testable too.

| Suite | Covers |
|---|---|
| `smp_test` | The scheduler on two real threads. Double-scheduling, sleep handover, affinity gating. |
| `task_test` | Spawn, exit, kill, slot reclamation, stack guards, and that the hardware guard follows the running task rather than the core. |
| `mpu_test` | Encoding a protection region on both architectures, every request that has to be refused rather than rounded, and what a real package span costs on each — the arithmetic behind leaving the package regions out of the RP2040 build. |
| `realapp_test` | Every real built package through the real loader, three ways: copied to RAM, copied to RAM sandboxed, and installed to a flash slot and loaded from it. Relocations, the GOT, the veneers, every branch by where it lands, and — since #103 — whether every code pointer it produced lands somewhere the hardware would let the CPU fetch from. Plus one synthetic object, for the relocation no compiler here emits. |
| `lock_test` | Recursion, hand-off, and that "busy" is per task rather than per core. |
| `packages_test` | dht, i2cscan, gpio and ws2812 against a fake device. |
| `calc_test` | The expression parser: precedence, associativity, errors. |
| `pio_test` | Instruction encoding, against the datasheet's tables. |
| `preempt_test`, `excframe_test` | The preemption policy and the exception frame. |
| `httpparse_test`, `httpfetch_test`, `repoindex_test`, `pkgindex_test` | HTTP, the package index, the installed list. |
| `tui_test`, `tuikey_test`, `tuilist_test`, `lineedit_test` | The screen layer and the line editor. |
| `rps_test` | The script interpreter. |
| `sdproto_test`, `fatro_test` | Bringing a card up, against a fake card written from the specification, and reading the filesystem on it, against volumes `fsck.fat` has approved of. |
| `radio_test`, `nfcframe_test`, `onewire_test` | Frequency and register arithmetic for the two SPI radios, and the frames and checksums the two contact readers carry. The bus transactions themselves need the chip. |
| `btadv_test`, `btname_test` | The advertising payload builders, byte for byte. |
| `crashlog_test` | The crash report text: header fields, log order and kind tags, a wrapped ring, and a buffer too small for it, checked for overruns with guard bytes. Rotating and writing the file needs a board. |
| `idle_test` | The idle auto-logout arithmetic: the setting parser (garbage, negatives and huge values all mean off or clamp) and the expiry test across the 32-bit millisecond wrap. The shell hook that uses it has run on a Pico 2 W: with a 1 minute timeout it logged out after 61 seconds and discarded a half-typed line. |
| `interrupt_test` | Ctrl+C and the console: the flag, the bounded read, the type-ahead stash (a numbered stream far larger than the ring comes out whole and in order, and a full stash stops reading rather than dropping the oldest), the claim a transfer or a line read holds, and that only the shell's own task reads the wire (another task sees the flag and nothing else). Reinstating drop-oldest, shrinking the ring, or removing the shell-only rule each fail it. |
| `clockcfg_test` | The boot clock policy: the frequency parser (range, suffix, junk, wrap-around) and the decision made at start — apply, already there, ignore a bad value, and skip after a start that did not finish. Setting the PLL itself is confirmed on a Pico 2 W: a clean restart comes up at the stored clock, a watchdog restart skips it, the next clean one applies it again. |
| `fwstream_test` | The radio firmware as the wireless images store it: deflated by `os/tools_cyw43fw.py`, read back through `core/fwstream.cpp` the way the patched driver reads it (the download in 64-byte bus blocks with a 40-byte last one, the CLM in one piece, the validity check on the stored 800-byte tail), and compared byte for byte with the SDK's own firmware header. Then damage: single-bit flips at 401 places, random byte damage (`RPC_FUZZ_ITERS`; 20,000 run clean), a wrong window CRC, cuts, a byte after the end, lengths that disagree, a stored block cut short, and a back-reference one byte past the 2 KB window. Each is refused, and none hands out a byte that differs from the original: the reader checks every window before giving out any of it, so nothing unchecked reaches the chip. It found uzlib reading `lookup_table[-3]` on a damaged stream (fixed, and marked, in `os/uzlib/tinflate.c`). Breaking the inflater, skipping the CRC, the end-of-input, end-of-stream or window-spanning checks, or generating with a larger window, each turns it red. Whether the radio comes up from it needs a board. |
| `fuzz_test` | Mutation fuzzing of the parsers that read other people's bytes: HTTP responses and URLs, the package index, the installed-package list, FAT12/16/32 volumes (with long names) and the shell's command-line scanners. 20,000 damaged inputs per target by default under AddressSan and UBSan; `RPC_FUZZ_ITERS` and `RPC_FUZZ_SEED` for a longer run. Each target also checks what its API promises, and the FAT target fails a volume that sends the reader round a loop or reads outside the volume its own header describes. It found `repo_version_cmp` reporting a suffixed version as newer than itself (so `pkg upgrade` offered the same upgrade for ever), `pkgindex_add` gluing a new package onto a line cut short by power loss, and a URL port that could overflow a 32-bit `long`. Eleven of twelve injected bugs were caught; the twelfth (the FAT chain-walk budget) only bounds how long a hostile seek takes. The package loader has its own: `fuzz_loader_test`. |
| `ssh_test` | The SSH protocol core against published values and a second implementation: RFC 4251 encodings, RFC 7748 X25519 vectors, the RFC 4253 key derivation rebuilt with the OS's own SHA-256, RSA, ECDSA and Ed25519 signatures and fingerprints made by `ssh-keygen`, the CTR MACs recomputed over the bytes the RFC names. The server's half of an Ed25519 login message by message: the query form answered with PK_OK, a request signed by RFC 8032's own code accepted, the same signature on another session refused. Then a client and a server core in memory with a misbehaving peer: an IGNORE injected before KEXINIT (Terrapin) is refused under strict key exchange, one byte past the window ends the connection, re-keying works from either end mid-stream. Built against mbedTLS with the device's configuration. |
| `ssh_fuzz_test` | Mutation fuzzing of everything an SSH peer can send: the plaintext before any key exists, an encrypted stream with bits flipped in transit (which must end the connection and never hand damaged data up), every service-layer message the server and the client parse, and `authorized_keys` / `known_hosts` text. An Ed25519 signature made by OpenSSH and an Ed25519 login request, damaged: whatever is accepted must be byte for byte what was signed. |
| `ed25519_test` | Ed25519 verification against RFC 8032: the five vectors of section 7.1, taken from the RFC's text by `gen_ed25519_vectors.py`; one-bit changes to signatures, keys and messages, and another vector's key, all refused; and the strict rules, with cases computed by the RFC's own section 6 code: S + L and other S out of range, keys and R values with y >= p or with x = 0 and the sign bit set, points not on the curve, and a signature that only a cofactored check accepts. Removing the range check, either decoding rule or the final comparison, or making the check cofactored, turns it red. Removing the decode of R does not: comparing with R's bytes already refuses every R that would not decode, and the decoding rule itself is tested on its own. |
| `ssh_interop` | `ssh_interop_test.sh`: the server core behind a loopback socket with the system's OpenSSH client forced through every key exchange, cipher and MAC in turn; RSA, ECDSA and Ed25519 user keys (the Ed25519 one through the query form, and a different Ed25519 key refused); exec with its exit status; 100 KB and 1 MB outputs, the second with a re-key every 16 KB; an interactive `ssh -tt` session; Ctrl+C; two sessions at once; refused keys, users and passwords, with the delay. Then the client core against that server and against an unprivileged OpenSSH `sshd`, whose ECDSA, RSA and Ed25519 host keys it verifies. Then the device's own server, `shell/sshd.cpp` unchanged, built against host fakes for the socket and the storage (`sshd_host.cpp`) with the real scheduler, accounts and output layer: an ordinary account over SSH cannot read the account file while root is at the console, a password-less one is refused by password and by key, a session's Ctrl+C does not reach the one beside it, vanished clients give their sockets back, a third connection is turned away, and `ssh server off` from inside a session stops it cleanly. SKIPPED, and counted as skipped, when there is no `ssh`. |
| `identity_test` | Who a command runs as, on real task switches with the real ident, users, perms, fsguard, protect and interrupt code: a guest logged in remotely while root is at the console cannot read protected files, run admin commands or use `sudo`, cannot touch root's `~/.ssh`, and its jobs stay the guest after it logs out; a remote root does not make the console's guest an admin; one session's Ctrl+C neither reaches nor clears another's. With the old global identity it fails 18 of 45 checks. |
| `perms_test` | What each command needs (anyone, an admin, or sudo) for every form that matters: the `pkg`, `update`, `ssh server`, `startup`, `task`, `service`, `autonomy`, `mkacct`, `passwd`, `safeboot`, `stock`, `reg set` and `run` rules, with a subcommand nobody listed needing sudo; the settings that decide who gets in; and, read from the shell's own sources, that each of those commands is registered with the level and rule the checks are about. |
| `sudo_test` | sudo end to end on real task switches, with the real sudo, perms, ident, users, file guard and persistence code and a scripted prompt: a system command without sudo is refused and says how; sudo asks once, three wrong passwords are refused and logged; the 5 minutes, restarting on use, and `sudo -k`; an ordinary account is never asked; root signed in by autonomy still needs the password; a background job uses its session's grace or is refused in one line without a prompt; a service runs with sudo; a remote login with a pty is asked on it, one without is told to use `ssh -t`, a job from it uses its grace, and a login started from a sudo'd task does not inherit it; link's `EXEC` never asks and `AUTH` lets the request through; a maintenance boot waives the password at the console's prompt only; and root without sudo cannot change `/os` or `/etc` while the registry and the account file are still saved. |
| `fuzz_loader_test` | Mutation fuzzing of the package loader, seeded with the packages `build.sh` produces. Damage is aimed at the section header table, symbol and string tables, relocation sections and the app header as often as at the file at large; every allocation the loader makes has an inaccessible page on both sides, and after each input all of them must have been given back, failure paths included. A second part builds the exact edges: a relocation one byte past its section, a Thumb branch on an odd address, a name table with no final NUL, an alignment that is not a power of two, a section too large to lay out, and the writable-data fixups of the one package that has them. It found four faults in the loader (see CHANGELOG, Packages). Twelve of thirteen removed fixes are caught; the thirteenth, the 64-bit sum in `read_exact`, is defence in depth behind the layout bound. |
| `features_py` | Feature selection (`tools/features.py`): each board's standard feature set, what `--with` and `--without` turn into for CMake (every option passed, a board refused a feature it cannot have, SSH going with Wi-Fi), the name a custom image gets, the settings file CMake includes, reading the variant marker out of an image, and `tools/buildconf.py` driven through its questions. `release_py` checks that a release refuses any image whose marker is not `standard`, including one read through a `.uf2`. That each custom build compiles, links, fits its slot and carries the marker it was asked for is checked by `build.sh` itself, on the image. |
| `rpc_tools` | The command-line tool (`tools/rpc`) against a pretend device written from the firmware's source: link mode as `os/shell/link.cpp` implements it, the prompt and its line editor, the login prompt and firmware without link mode, with CRLF endings and background lines dropped between frames. Every `rpc` command, entering link mode from each state the console can be left in, Ctrl+C mid-transfer, digest errors both ways, timeouts on both sides, and Unicode paths. Runs with plain `python3`; with pyserial installed one test also drives the real serial library over a pseudo-terminal. Nothing touches a real port. |
| `web_link_js` | The browser tool's protocol client (`tools/web/js/link.js`) and repository rules, against a JavaScript twin of that pretend device. Needs `node` (20 or later) or `deno`; without either the line says it was not run, and it is not counted. |

## What needs a board

Everything above runs on the host. These do not, and each has caught something the host
suites could not.

| Check | Run with | What it asks |
|---|---|---|
| Smoke test | `tools/devsmoke.py` | Does the OS still start, install and run a package, render Nova D1, and enforce the memory protection unit. One pass of a few seconds. |
| Recovery ladder | `sudo failboot 2`, then `reboot`; `sudo failboot 3` | The third failed start loads nothing (`ps` shows no package tasks; the log has `Maintenance boot`). The fourth restores the saved firmware and the device reports `Rolled back`. `failboot` exists because a build that genuinely will not start cannot be flashed off the device afterwards. It found that the start count was overwritten by the SDK before it was read. |
| sudo | `pkg install` (refused), `sudo pkg install`, `sudo -v`, `sudo -k`; `ssh dev 'sudo ...'` and `ssh -t dev 'sudo ...'`; `rpc install` with and without `RPC_PASSWORD`; `safeboot`, then `sudo usermod root passwd` at the console | The prompt on the real console and an SSH terminal, the grace on the board's clock, `AUTH` through a real USB console, and that a maintenance boot lets the console through and nothing else. |
| Rollback | `sudo update rollback --save`, `sudo update rollback --now` | A saved image is written back and the device comes up on it. `version` shows the build. |
| Host tools | `rpc info`, then `rpc put`, `get`, `exec`, `install` and `backup`; `rpc web` in Chrome | What the pretend device cannot show: the USB console's own timing and buffering, how long a real flash write holds up an ACK, the 1200-baud reset and the BOOTSEL drive appearing on each system, and Web Serial on a real port. |
| Radio firmware | `wifi scan`, `wifi connect`, `bt` scanning, `log` | The radio comes up from the deflated firmware (`os/cyw43_fw.cpp`), joins, and Bluetooth starts; and how much longer bringing it up takes than on a build configured with `-DRPC_CYW43_FW_STREAM=OFF`. Not yet run on a board. |
| Soak | `tools/soak.py` | Samples uptime, heap, filesystem and tasks every few minutes for days and makes an HTTPS request hourly. A reset, a full filesystem or a failed request is written down with the log that explains it. |
